# Bug: Availability page time dropdown doesn't open on click

**Where:** `/availability` — Weekly hours grid, every start/end time control (e.g. clicking "9:00 AM" does nothing). Also latent in any other `TimeCombobox` usage outside a modal `<Dialog>`.

**How it was found:** User reported clicking the time dropdown produced no visible change. Static review of the click/ref/context wiring in `components/ui/time-combobox.tsx`, `components/ui/popover.tsx`, and `components/ui/slot.tsx` (all part of the in-progress Radix → Headless UI / `@floating-ui/react` / DaisyUI migration) found no defect and `next build`/`tsc` passed clean. Reproduced live with an isolated Playwright script against a throwaway test route rendering `TimeCombobox` outside auth: clicking the trigger correctly flipped `data-state` to `open`, but `[data-slot="popover-content"]` never appeared in the DOM and no console error was thrown. A control test against `components/ui/country-combobox.tsx` (same `Popover`/`asChild` pattern, no `container` prop) worked fine, and against `booking-calendar.tsx`'s date-picker `Popover` (also no `container` prop) worked fine — isolating the defect to something specific to `TimeCombobox`.

**Root cause:** `TimeCombobox` initializes `const [container, setContainer] = useState<Element | null>(null)` and, on open, resolves it via `triggerRef.current?.closest('[role="dialog"]') ?? null` — intended to portal the dropdown into an ancestor `<Dialog>` (so it stays inside the dialog's scroll-locked region) or fall back to the default body portal otherwise. That `container` value is passed straight through as `PopoverContent`'s `container` prop → `FloatingPortal root={container}` (`components/ui/popover.tsx`).

`@floating-ui/react`'s `useFloatingPortalNode` special-cases a literal `root === null` to mean "the root hasn't resolved yet, wait" (`node_modules/@floating-ui/react/dist/floating-ui.react.esm.js:1684`) and never creates the portal node in that case — it does **not** fall back to the default body portal the way `root === undefined` (i.e. the prop simply omitted) does. Since every `TimeCombobox` trigger on `/availability` sits outside any `<Dialog>`, `.closest('[role="dialog"]')` always returns `null`, so `container` is permanently `null`, and `FloatingPortal` permanently declines to mount — with no thrown error, since floating-ui just silently no-ops.
